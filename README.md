# HTML 答疑前端

把任意单文件 HTML（尤其 2L 生成的讲义）打开，**选中一段文字，右侧直接问 AI**。

## 在线地址（手机直接用这个）

**https://wuyudashui.github.io/HTML-**

手机浏览器打开即可，不需要局域网、不需要电脑开机、不需要装任何东西。
仓库：https://github.com/wuyudashui/HTML-

打开后：点 **＋** 选讲义 → 点 ⚙ 填 API Key → **长按正文选中一段** → 点「解释这段」。
API Key 只存在你自己手机的浏览器里，不会上传到 GitHub 或任何服务器。

也可以双击 `index.html` 本地使用 —— 不需要安装、不需要起服务、可离线。

## 怎么用

**电脑**

1. 双击 `index.html`
2. 点「＋ 打开 HTML」或把 `.html` 文件直接拖进窗口（可一次拖多个，顶部变标签页）
3. 点右上角 ⚙ 填 **API Key / Base URL / 模型名**，先点「测试连接」
4. 用鼠标选中一段文字 → 浮条出现 → 选「解释这段」或「提问…」

快捷键：`Ctrl+O` 打开文件；`Enter` 发送、`Shift+Enter` 换行；`Esc` 收起浮条。

**手机（推荐：直接用在线地址）**

打开 **https://wuyudashui.github.io/HTML-** 即可，步骤同上：**＋** 选讲义 → ⚙ 配 API →
长按选中 → 「解释这段」。AI 面板是全屏抽屉，点右上角 **✕** 或点抽屉外遮罩收起。

**手机（备选：局域网）**

不想依赖外网、或要用尚未上传的讲义时，在自己电脑上起服务：

1. 电脑上双击 **`手机使用.cmd`**
   - 窗口里会打印类似 `http://192.168.1.23:8770/` 的地址（本机是 `http://10.162.81.5:8770/`）
   - 第一次运行 Windows 防火墙会弹窗，**必须点「允许访问」**，否则手机连不上
2. 手机连**同一个 Wi-Fi**，浏览器打开那个地址
3. 后续步骤同上

> 打不开时按这个顺序查：防火墙是否放行 → 网络类型是不是「公用网络」（要改成专用）→
> 路由器有没有开「AP 隔离 / 客户端隔离」。`手机使用.cmd` 关闭后服务就停了。

## 手机适配做了什么

窄屏（≤900px）不只是把面板压窄，几处交互是分开处理的：

| 项目 | 手机上的行为 |
|---|---|
| AI 面板 | 全屏抽屉 + 暗色遮罩 + **✕** 关闭；冷启动默认收起，不会一进来就盖住内容 |
| 选中文字 | 触屏不会可靠触发 `mouseup`，因此额外监听 `selectionchange` / `touchend`（防抖 180–220ms） |
| 浮条位置 | 贴顶时自动下移到选区下方；左右按视口夹紧，不会跑出屏幕 |
| 浮条尺寸 | 按钮最小高度 38px，避免误触 |
| 选区快照 | 浮条出现时就存下文本与所在小节；**点击前选区被折叠也仍能拿到原文** |
| 软键盘 | 用 `visualViewport` 约束抽屉高度，输入框不会被键盘盖住 |
| 顶栏 | 品牌文字隐藏、「打开 HTML」收成 ＋，标签页横向滚动 |
| 设置 | 变成底部弹层，按钮换行、输入框 44px 高 |
| 视口 | `100dvh` + `viewport-fit=cover` + `env(safe-area-inset-*)` 适配地址栏与刘海 |
| 输入框 | iOS 上字号提到 16px，避免聚焦时页面被自动放大 |

## AI 配置

兼容 **OpenAI Chat Completions** 协议的服务都能用。Base URL 三种写法都认：

| 你填的 | 实际请求 |
|---|---|
| `https://api.deepseek.com` | `https://api.deepseek.com/v1/chat/completions` |
| `https://api.deepseek.com/v1` | `https://api.deepseek.com/v1/chat/completions` |
| `https://x/v1/chat/completions` | 原样使用 |

对话框里会实时显示「实际请求：…」，不用自己拼。默认模型名 `deepseek-chat`。

### ⚠ 两个必须知道的限制

**1. 浏览器直连受 CORS 限制。**
这是浏览器安全策略，与 Key 正确与否无关。如果目标 API 不允许跨域，请求会失败，
界面会明确告诉你可能是 CORS，而不是笼统报错。此时需要改用允许跨域的端点或自建代理。

**2. API Key 以明文存在本机 localStorage。**
只在你点「发送」时发往你填的那个地址，不经任何第三方。公用电脑上用完请点「清除」。

## 为什么刷新后要重新拖文件

**这是刻意设计，不是缺陷。** 一份 2L 讲义约 **1.7 MB**（KaTeX 字体已 base64 内嵌），
而 `localStorage` 只有约 5 MB —— 存不下几个。
要真正「存起来」需要 IndexedDB + 本地 HTTP 服务（`file://` 下 IndexedDB 不可靠）。
当前版本选择了「零依赖、双击即用」，代价是文件不持久化：**每次打开重拖即可**。

如果更看重持久化，见文末「后续可选」。

## 目录

```
D:\GPT\
├─ index.html          全部界面与逻辑（单文件）
├─ assets/katex/       KaTeX（可选）：AI 回答里的公式靠它渲染
├─ 手机使用.cmd        手机用：双击启动局域网服务（纯 ASCII 包装器）
├─ start-mobile.ps1    上面那个的实际逻辑（探测可用 Python、打印局域网地址）
└─ README.md
```

**两个脚本文件的作用**：`手机使用.cmd` 只是两行包装，真正干活的是 `start-mobile.ps1`。
之所以不把逻辑写进 `.cmd`，是因为批处理按 ANSI 码页读取文件，中文注释会被拆成伪命令；
而 IP 探测需要 PowerShell 管道，`.cmd` 又会把命令里的 `|` 当成自己的管道符。
`.ps1` 带 UTF-8 BOM，Windows PowerShell 5.1 才能正确读中文。

**KaTeX 是可选的。** 删掉 `assets/katex/` 也能正常用，只是回答里的公式退化成原文。
已实测：缺失时页面照常启动、照常提问、无未捕获异常。

## 实现里两个值得留意的点

### srcdoc 兼容 shim（为什么代码里有段看起来多余的东西）

讲义页面被放在 `srcdoc` iframe 里渲染，其文档 URL 是 `about:srcdoc`。
2L 讲义自带的 `navigation.js` 会调用
`history.replaceState(null, '', '#chapter-1')`，在 `about:srcdoc` 下必然抛：

```
SecurityError: A history state object with URL '...' cannot be created
in a document with origin 'file://' and URL 'about:srcdoc'.
```

**危害不只是控制台一条红字**：`show()` 里是先 `replaceState`、后 `scrollIntoView`，
异常一抛，后面那步被跳过 —— 切换要点后不滚回顶部，长讲义里就会停在中段。

因此打开文件时会往 HTML 的 `<head>` 后注入一小段脚本，把
`history.replaceState/pushState` 置为空函数。已用 A/B 实测：

| | 报错 | 切换后滚动 |
|---|---|---|
| 不注入 shim | `SecurityError` | 不滚动（`0 → 0`） |
| 注入 shim | 无 | 正常滚动（`0 → 693`） |

### 标签页显示讲义标题，而不是文件名

2L 导出的文件常常都叫 `讲解.html`，光看文件名分不清是哪一科。
所以显示名取 HTML 的 `<title>`，真实文件名降为悬停提示。
